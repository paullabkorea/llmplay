# 이미지·음성의 비밀 | AI는 사진과 소리를 어떻게 읽을까?

## 이 장이 전하려는 것

- 언어 모델(LLM)은 **글자(토큰)만 읽는 뇌**다. 사진과 소리는 그대로 넣어도 읽지 못한다.
- 그래서 **눈·귀·손 역할을 하는 전용 모델**이 붙는다. 사진은 조각(패치)으로, 소리는 시간 조각과 받아쓰기로 바뀌어 전달된다. 읽는 방식이 글과 다르다.
- 번역 과정에서 **정보가 흐려진다.** 작은 글씨는 뭉개지고, 말투·억양은 받아쓰기에서 사라진다.
- **이미지 수정은 매우 어렵다.** 언어 모델은 주문서(글)만 쓸 수 있고, 이미지 생성 모델은 처음부터 다시 그린다. 부탁하지 않은 곳까지 바뀐다.
- 따라서 **멀티모달을 지원하는 플랫폼·모델을 잘 골라야** 하고, **AI에게 정보를 줄 때는 글이 있으면 글로 주는 것**이 좋다.

대상은 다른 페이지와 같은 중·고등학생과 비전공자다. 파일을 올리거나 자르는 실습은 없다. index.html처럼
**자동 재생 / 한 단계씩 / 처음부터** 버튼으로 눈으로만 따라가며, 단계마다 말풍선 설명이 관련 패널 위에 뜬다.

위치: '학습의 비밀' 다음, '모델의 비밀' 앞. 앞에서 배운 토큰과 숫자 변환을 사진·소리로 확장한 뒤,
다음 장의 '작업에 맞는 모델 고르기'로 이어진다.

## 화면 구성

세 패널이 `내가 보낸 것 → 전용 모델 → 언어 모델` 순서로 놓이고, 데모에 따라 패널 제목이 바뀐다.

```
[내가 보낸 것]        [전용 모델: 눈]           [언어 모델 (LLM)]
집 사진 + 질문     →  8×8 조각 → 숫자 묶음  →  🖼 읽을 수 없음 → 숫자 묶음 64개 + 토큰
                                                 → "초록 지붕과 파란 문이 있는 집이에요"
```

## 데모 4개 (각 5~6단계, 약 20초)

| 데모 | 흐름 | 학생이 가져갈 한 문장 |
| --- | --- | --- |
| 1. 사진을 보내면 | 사진+질문 → 언어 모델 문 앞에서 막힘 → 눈 모델이 조각내기 → 숫자로 → 전달 → 글로 답 | 언어 모델은 사진을 본 게 아니라 번역된 숫자를 읽는다. 조각보다 작은 글씨는 뭉개진다. |
| 2. 목소리를 보내면 | 비꼬는 "정말~ 잘했네" → 소리 못 들음 → 귀 모델이 시간 조각 → 받아쓰기 → 글만 전달 → 칭찬으로 오해 | 받아쓰기에는 말투가 없다. 음성 기능이 있다고 다 같은 게 아니다. |
| 3. 사진을 고쳐 달라고 하면 | 사진+"지붕만 보라색" → 언어 모델은 글만 출력 → 주문서 작성 → 손 모델이 처음부터 다시 그림 → 비교 → 정리 | 이미지 수정은 '다시 그리기'라 세부가 흔들린다. 정밀한 수정은 편집 도구로. |
| 4. 같은 정보, 사진 vs 글 | 캡처 사진과 글 → 사진의 길(조각 64개, 숫자 뭉개짐) → 글의 길(토큰 9개) → 답 비교 → 정리 | 같은 정보라면 글로. 사진은 사진이어야만 할 때만. |

데모 아래에 **네 가지 데모 카드**(누르면 그 데모로 전환), **그래서 어떻게 할까요?**(플랫폼 고를 때 확인할 것 / AI에게 정보 줄 때),
**핵심 개념** 팝오버(멀티모달, 전용 모델, 조각, 이해 vs 생성, 진짜로 듣는 모델, 실제와 다른 점)가 이어진다.

## 수업 흐름 (약 20분)

1. **질문 던지기 (2분).** "ChatGPT에 사진을 넣으면 답을 하잖아요. 그럼 언어 모델이 사진을 보는 걸까요?" 손을 들게 한다.
2. **데모 1 (5분).** 한 단계씩 누르며 진행한다. 4단계에서 멈추고 "OPEN 글씨가 아직 보이나요?"를 묻는다.
3. **데모 2 (4분).** 1단계에서 "정말~ 잘했네"를 직접 비꼬는 말투로 읽어 준다. 6단계의 답을 보고 왜 오해했는지 말하게 한다.
4. **데모 3 (5분).** 5단계의 비교 목록을 함께 읽는다. "지붕만 바꿔 달라고 했는데 왜 창문이 늘었을까?"
5. **데모 4와 정리 (4분).** 답 비교를 본 뒤 '그래서 어떻게 할까요?' 두 카드를 읽는다.

## 확인 질문

1. 언어 모델은 사진 파일을 직접 읽을 수 있나? → 아니다. 전용 모델이 숫자 묶음으로 바꿔 줘야 한다.
2. 받아쓰기를 거친 음성에서 사라지는 것은? → 억양, 강조, 말투, 배경 소리.
3. "지붕만 바꿔 줘"라고 했는데 창문까지 바뀐 이유는? → 언어 모델은 주문서만 쓰고, 생성 모델이 처음부터 다시 그리기 때문.
4. 표를 AI에게 줄 때 캡처와 글 중 무엇이 좋은가? → 글. 뭉개지지 않고 토큰도 적다.

## 교사용 주의 (공식 문서로 확인한 범위, 2026-09-13)

- 모자이크와 숫자 3개는 모형이다. 실제 모델의 조각은 28×28(Claude)·32×32(OpenAI)픽셀로 아주 작아 또렷한 글씨는 잘 읽는다.
  "AI는 원래 이렇게 흐리게 본다", "조각 64개 = 토큰 64개"로 결론 내리지 않는다. 공식 문서가 밝힌 약점은
  작거나 흐린 글씨, 축소된 이미지, 개수 세기, 정확한 위치다.
- 토큰 수치: Claude 문서 기준 1000×1000 사진 한 장은 토큰 1,296개. 같은 표를 글로 쓰면 수십 개. "사진이 수십 배 비싸다"는 이 근거로 말한다.
- 소리: OpenAI 음성 문서는 '음성 인식 → 텍스트 모델 → 음성 합성' 연결과 '소리 직접 처리' 두 경로를 구분한다.
  데모 2는 받아쓰기 경로이며, 어느 경로인지는 서비스와 모드마다 확인해야 한다고 덧붙인다.
- 이미지 생성·편집: Claude는 공식 FAQ에서 이미지를 생성·편집하지 않는다고 밝힌다. ChatGPT는 별도 이미지 모델을 붙여 쓴다.
  원본을 함께 보고 그리는 편집 기능이 있어 예전보다 나아졌지만, 여전히 "그리기"라 글자·세부가 흔들린다는 수준으로 설명한다.
- 답변 문장은 미리 써 둔 예시다. 실제 AI를 호출하지 않는다.

## 구현과 검증 범위

- `multimodal.html`: 세 패널 스테이지, 조작부, 데모 카드, 정리, 핵심 개념.
- `js/multimodal/player.js`: 단계 상태 기계. `scenarios.js`: 데모 4개의 단계 설명과 패널 그리기.
- `js/multimodal/draw.js`: 집 그림(원본·다시 그린 것), 격자, 모자이크, 파형, 표 캡처. `fx.js`: 타자·생성 연출.
- `js/multimodal/model.js`: 조각 평균 색, 시간 조각 세기, 목소리 모형, 세부 생존 규칙.
- `tests/multimodal.test.mjs`: 조각 계산, 목소리 모형, 다시 그린 집의 차이, 시나리오 구조 검증.
